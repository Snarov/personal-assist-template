# Personal Assist / Персональный ассистент

Пустой шаблон личного ассистента. Дневник, ритуал, заметки и заполненный каталог сюда не входят: их заводит владелец у себя.

Задачи — в его личном Notion. Облачные агенты клонируют репозиторий из `catalog.json` → `github.repo`, а не эту папку на чужой машине.

## Что внутри

| Путь | Зачем |
| --- | --- |
| `.cursor/environment.json` | Облачный environment **Personal Assist** |
| `.cursor/mcp.json` | Только MCP `notion-personal` |
| `catalog.json` | Ссылки на личный Notion и Telegram-реле |
| `AGENTS.md` | Правила для агента |
| `.cursor/skills/` | Утро, вечер, ответ из Telegram, дневник (`life-journal`), рабочая рутина (`routine-log`), учёба (`study-log`), свободные заметки (`free-notes`), Notion cleanup |
| `.cursor/rules/ritual-memory.mdc` | Открытые пропуски утро/вечер — агент видит их в правилах |
| `.cursor/rules/task-nudges.mdc` | Утро само проходит открытые задачи и коротко напоминает окно срока: старт, середина, конец |
| `ritual/` | MD-итог каждого дня (`YYYY-MM-DD.md`) |
| `journal/` | Дневник: спека, профиль, опрос волнами утро/вечер (`survey-script.json`), дни |
| `routine/` | Отдельный JSON-лог обычной работы вне фокус-задач: дела, минуты и насколько это отвлекло |
| `study/` | Учёба в будни: 30 минут в день, недобор переходит дальше. Суббота и воскресенье не начисляют. Что выучено и к какой цели, проекту и задаче это привязано. Тема — в Notion, база «Учёба» |
| `notes/` | Свободные заметки: идея, опыт, воззрение — не задачи, не дневник здоровья и не «как прошёл день» |
| `telegram-relay/` | Тонкий бот на хосте из `catalog.json` → `deploy.host`: агенты шлют сообщения, владелец отвечает. Ответ ставится в `/inbox` и должен поднять облачный прогон `telegram-feedback`. |
| `automations/` | Текст промпта для webhook-автоматизации на ответ из Telegram |

## Notion

Личный Notion — отдельное пространство владельца. В Cursor к нему подключается только сервер `notion-personal`. Чужие пространства, которые нельзя трогать, перечисляются в `catalog.json` → `notion.forbiddenWorkspaces`.

Адреса досок и реле — в `catalog.json`.

## Ответ из Telegram

Утро и вечер стартуют по расписанию. Ответ владельца реле кладёт в `/inbox`. Несколько голосовых подряд — одна очередь и один облачный прогон `telegram-feedback` (пауза ~6 минут между запусками, `RELAY_LAUNCH_COOLDOWN_SEC`). Если запуск не удался, сообщение остаётся в очереди: его разберёт этот же ритуал (ждёт до 90 минут) или следующий утренний/вечерний прогон. Минуты, прогресс и итог идут в поля цикла/задачи; свободная мысль по задаче — в комментарий карточки (`telegram-feedback` → Task comments). Идея, опыт или воззрение, которые не про задачу, не про дневник здоровья и не про то, как прошёл день, пишутся в `notes/entries/` (`free-notes`).

Реле сразу ставит 👀 на сообщение и отвечает «Принял.» — так видно, что бот жив, пока облачный агент думает (часто 2–5 минут). Если расшифровка или запуск сломались — отдельное сообщение об ошибке. Когда агент стартовал, реакция меняется на ⚡.

На хосте из `catalog.json` → `deploy` в `relay.env` нужен **хотя бы один** из вариантов:

1. Webhook-автоматизация «Telegram feedback» — см. `automations/telegram-feedback.md`. Egress: `catalog.json` → `deploy.egressNote`.
2. `CURSOR_API_KEY` из [Dashboard → API Keys](https://cursor.com/dashboard?tab=integrations).

Реле само архивирует **законченные** ритуальные чаты (`Personal assist telegram feedback` / `morning check-in` / `evening review`), чтобы они не забивали список Agents. Внутренний тул агента умеет только читать прогоны, архивирует публичный Cloud Agents API: `POST /v1/agents/{id}/archive`. Ключ нужен даже если запуск идёт через webhook. Живой утренний/вечерний прогон (ждёт ответ до 90 минут) не трогаем — только `IDLE`.

После правки `relay.py` с машины с SSH: `./telegram-relay/deploy.sh` ставит инстанс из `catalog.json` и перезапускает только его юнит. Другой инстанс на том же хосте: `./telegram-relay/deploy.sh telegram-relay/instances/example.json` после того, как в этом файле заполнены свои пути. Без токена бота и chat id юнит не включается.
